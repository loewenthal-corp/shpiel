# Security Policy

## Supported versions

Shpiel is pre-1.0 and ships from `main`. Security fixes land on `main`
and in the most recent tagged release; older tags are not patched.

| Version | Supported |
| ------- | --------- |
| latest release / `main` | :white_check_mark: |
| older releases | :x: |

## Reporting a vulnerability

Please report security vulnerabilities privately — do **not** open a
public issue for anything exploitable.

- Preferred: use GitHub's [private vulnerability reporting](https://github.com/loewenthal-corp/shpiel/security/advisories/new)
  ("Report a vulnerability" under the repository's **Security** tab).
- Alternatively, email **security@loewenthal.net**.

Please include enough detail to reproduce: affected version or commit,
configuration, and a proof of concept where possible.

## What to expect

- We aim to acknowledge a report within **3 business days**.
- We will keep you updated on our assessment and remediation progress.
- Once a fix is available we will coordinate a disclosure timeline with
  you and credit you in the advisory unless you prefer otherwise.

Thank you for helping keep Shpiel and its users safe.
